Ratman project — 软件需求
3D 点云中的水下目标检测与分割
版本：0.2 | 状态：供双方共同审阅的草案
适用方：Ratman project 与 TU Clausthal

1. 项目目的
开发一套集成所选深度学习框架的软件，用于模型训练，以及自动检测和分割 3D 点云中的水下目标。软件应计算目标属性、导出分割后的目标点云，并生成结构化检测报告。

2. 输入数据及委托方提供的材料
REQ-01 Ratman project 应提供已完成地理配准的 LAS（*.las）或 LAZ（*.laz）格式 3D 点云及其关联的全波形数据。如果波形采样数据单独存储，还应提供相应文件及其与点云的关联信息。
REQ-02 数据集说明应注明各数据集的用途（训练或测试），并在相关时注明采集地点。
REQ-03 使用已有的坐标参考系和传感器信息，并记录坐标单位与高程基准。
REQ-04 检测与分割范围以双方已商定的水下目标类别为准。
REQ-05 目前提供的点云没有标注。在开展监督学习训练前，应商定所需标注、标注责任、工作量及质量检查方式。本草案不默认 Ratman project 已完成标注，也不默认标注工作自动纳入本次范围。

3. 数据准备及模型训练
REQ-06 软件应能导入 LAS/LAZ 点云，检查必需属性及波形数据是否可用，并对不支持或不完整的输入进行提示。
REQ-07 数据准备应生成适用于所选深度学习框架的输入，同时保留与原始点及地理配准坐标的对应关系。
REQ-08 软件应支持使用商定的训练数据及标注进行模型训练，并允许配置训练参数。
REQ-09 应分离训练集、验证集和测试集，避免数据泄漏。验证集用于模型选择，测试集用于独立评估。具体划分方式由双方商定。
REQ-10 训练后的模型应可保存和重新加载，并同时保存模型版本、类别定义及所需的预处理配置。
REQ-11 深度学习框架、模型架构、是否使用预训练权重、波形表示方式及训练策略应在方法评估阶段确定。本草案不预先指定某一框架或准确率水平。

4. AI 检测及目标分割
REQ-12 软件应能够加载已训练模型，并对新数据进行推理。
REQ-13 软件应检测商定的目标，并将点分配给各个独立目标实例。仅输出类别预测不足以生成每个目标的独立记录。
REQ-14 每个检测到的目标应在本次运行中具有唯一的目标 ID。跨越处理分块边界的目标应进行合并或一致性处理，避免重复记录和点数不一致。
REQ-15 软件应为每个检测目标计算一个目标级置信度值。分数定义、从点级分数汇总到目标级分数的方法（如适用）以及筛选阈值应有记录并由双方商定。置信度不应被表述为实测的检测准确率。

5. 目标属性
REQ-16 软件应为每个分割后的目标计算以下属性：
       - x、y、z：该目标所有所属点坐标的算术平均值，即点云几何中心，使用商定的坐标参考系。该中心不一定等同于真实物体的物理中心。
       - Nr_of_points：导出目标所包含的点数。
       - Intensity：目标点的强度统计值。建议默认采用有效输入强度值的算术平均值。最终定义及缺失值处理方式需确认。
       - Area：按商定定义计算的目标面积，单位为平方米。待确定采用水平投影面积还是三维表面积。重建或投影方法及参数须商定，不应使用未说明的默认面积算法。
       - confidence：REQ-15 所定义的目标级置信度。
REQ-17 属性应基于商定输出分辨率下的最终目标分割结果计算。影响这些数值的降采样操作应予以记录。缺失属性应明确标记，不应直接以零代替而不作说明。

6. 单个及批量处理
REQ-18 软件应支持一次处理一个输入数据集。
REQ-19 软件也应支持使用选定模型和处理配置，批量处理多个数据集。
REQ-20 批处理应保留每个目标的来源数据集标识，记录各数据集的完成或失败状态，并报告错误。无效输入不应在没有提示的情况下导致整个批次失效。

7. 导出及报告
REQ-21 除检测报告外，软件应将每个检测目标的 3D 点云分别导出为 CSV 文件，文件名为 <object_ID>.csv，使用与报告和可视化中一致的检测 ID。每行代表一个点，至少包含原始地理配准坐标系中的 x、y、z 坐标。其他点属性由双方商定。目标 ID 应在整个批次内唯一，避免目标点云文件相互覆盖。
REQ-22 软件应生成可由程序读取的检测报告，每个目标占一行。建议表头顺序为：

       object ID | x | y | z | Nr_of_points | Intensity | Area | confidence

       中文含义：目标 ID | x 坐标 | y 坐标 | z 坐标 | 点数 | 强度 | 面积 | 置信度

REQ-23 建议采用 CSV 报告格式。最终格式、表头、数值精度、单位及缺失值表示方式应在完成实现前由 Ratman project 确认。
REQ-24 应通过按数据集分别生成报告，或在批量汇总报告中增加来源字段，保留目标与来源数据集的对应关系。此选择需双方商定，不应擅自改变建议表头。
REQ-25 运行摘要或配套元数据文件应记录模型版本、处理设置、坐标参考系、面积/强度/置信度定义及处理错误。未检测到目标应与处理失败明确区分。

REQ-34 每次处理应创建一个结果文件夹，命名为 <输入文件名（不含扩展名）>_<YYYYMMDD_HHMMSS>，时间采用本次运行开始时间。单个处理使用当前输入文件名；批处理整个批次只创建一个共用的结果文件夹，使用批处理输入列表中的第一个文件名作为代表。报告、目标 CSV 文件和运行元数据均保存在该文件夹内，可按需设置子文件夹。如果同名文件夹已存在，应添加唯一后缀，不得覆盖之前的结果。例如：survey01_20260921_143025/objects/0001.csv。

8. 平台及软件封装
REQ-26 软件应支持在 Windows 和 Linux 上安装运行。支持的操作系统版本以及训练、推理所需的 CPU/GPU 条件应由双方商定并记录。
REQ-27 所选框架及依赖应整合到各支持平台上可重复执行的安装流程中。
REQ-28 软件应提供图形界面，包含下述 View 和 Show objects 控件。软件界面应提供训练、模型选择、单个/批量推理及导出设置入口。额外的命令行界面为可选项，是否提供另行商定。

8.1 处理完成后的点云可视化
REQ-35 点云处理成功完成后，用户应能够点击 View 显示处理后的点云，并在交互式三维视图中旋转、缩放和平移。查看已完成的结果不应要求重新运行处理。批处理模式下，用户应能够选择某个已成功处理的数据集进行查看。
REQ-36 打开点云后，用户点击 Show objects（显示目标），应将检测到的目标点以区别于背景点云的颜色高亮显示。不同目标实例应使用可区分的颜色，并通过图例或选中目标查看对应 ID。用户应能够关闭和重新开启目标高亮。可视化中的 ID 应与检测报告及导出的目标 CSV 文件名一致。如果未检测到目标，应在视图中明确提示。

9. 验证及验收
REQ-29 功能验证应覆盖导入、训练及模型重新加载、实例分割、单个/批量执行、属性计算和导出；还应检查 View/Show objects 功能、各类输出中目标 ID 的一致性、CSV 点数，以及单个/批处理的结果文件夹命名。
REQ-30 应根据导出的目标点核对目标 ID、点数及几何中心计算。面积计算应在选定面积定义下，使用商定的参考案例核查。
REQ-31 检测及分割质量应通过独立留出数据进行评估，使用参考标注或商定的专家审查方式。量化指标和验收阈值应在最终测试前商定。
REQ-32 应在确认的 Windows 和 Linux 环境中验证安装及商定的工作流程。
REQ-33 Ratman project 应确认所提出的报告格式、内容及部署要求。TU Clausthal 应实施双方商定的设计。

10. 交付成果
- 支持训练、单个/批量推理及结果可视化的软件包。
- 已训练模型及其相关配置。
- 商定测试数据的逐目标 CSV 点云文件及检测报告。
- 安装及使用说明，以及最终项目报告。
- diagrams.net/draw.io 格式的可编辑软件架构图。

11. 尚需确定的事项
- 标注责任、标注工作量及数据集划分。
- 深度学习框架、训练策略及波形输入表示方式。
- 面积定义及计算方法。
- 强度统计方式、置信度定义及筛选阈值。
- 报告格式、点云 CSV 的附加属性、来源数据对应关系及数值精度。
- 图形界面详细设计、可选命令行界面、操作系统版本及硬件要求。
- 数据集大小限制及量化验收标准。

本文件为技术需求草案，不修改现有报价、人员工时分配或交付时间安排。商定需求所涉及的任何新增工作均需与现有项目范围协调一致。
